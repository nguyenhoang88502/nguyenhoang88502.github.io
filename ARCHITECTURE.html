1. Overview & Site Map

This repository is a static GitHub Pages site: HTML, CSS, JavaScript, images, PDFs, and data artifacts organized into project folders. There is no build step, no bundler, and no server-side rendering. Every folder with an index.html is a routable subpage.

// Public URL structure https://nguyenhoang88502.github.io/ → index.html (portfolio) https://nguyenhoang88502.github.io/OPF_sim/ → OPF_sim/index.html https://nguyenhoang88502.github.io/WMS/ → WMS/index.html https://nguyenhoang88502.github.io/manufacturing-failure.../ → manufacturing-failure.../index.html

The root index.html is the personal portfolio landing page. It contains:

  • Hero section with name, photo, description, and CTA buttons
  • Education & Certifications cards
  • Skills & Tools (4 cards: Data, Optimization, Tools, Software Dev)
  • Work Experience timeline (Wahl Clipper Vietnam + 7-Eleven)
  • Extracurricular Activities timeline (3 entries)
  • Projects grid (9 project cards)
  • Contact section (email, phone, LinkedIn, location)
  • AI Chat Widget (bottom-right launcher)
  • EN/VI language toggle in the navbar

No hardcoded font-size overrides in media queries. All typography uses clamp() for fluid scaling. The 767px breakpoint that previously forced font-size: 3.5rem on the hero name has been removed.

4. JavaScript Architecture

5. Language Toggle / i18n System

5.1 Translation Dictionary

All translations live in a single const I18N object in the second inline <script> block. It has two top-level keys: en and vi. Each contains ~80 translation entries organized by section prefix:

I18N ├── en │ ├── nav.* // 7 navbar links │ ├── hero.* // eyebrow, desc (HTML), cta, resume │ ├── edu.* // label, title, degree, grad, gpa, certs, english │ ├── skills.* // label, title, data, opt, tools, dev │ ├── exp.* // label, title, wahl.* (date/company/role/b1-b4), seven.* │ ├── extra.* // label, title, bkfc.*, plec.*, ymu.* │ ├── projects.* // label, title │ ├── proj.01.* ... proj.09.* // cat, title, desc (some with HTML) │ ├── contact.* // label, title, email, phone, location │ └── footer.* // tagline └── vi // Mirror structure with Vietnamese text
Key naming convention: section.sub.key using dot notation. Keys ending with HTML content use data-i18n-html attribute; plain text keys use data-i18n.

5.2 Toggle Flow

// User clicks EN or VI button 1. click event on .lang-toggle 2. Read data-lang attribute ("en" | "vi") 3. Set currentLang = lang 4. localStorage.setItem("lang", lang) 5. Call applyLang(lang): ├── window.__siteLang = lang ├── document.documentElement.lang = lang ├── Walk all [data-i18n] elements → set textContent ├── Walk all [data-i18n-html] elements → set innerHTML ├── Update .lang-toggle active-lang class └── Call window.__setChatLang(lang) // updates chat widget

5.3 HTML Markers

AttributePurposeExample
data-i18n="key" Plain text replacement via textContent <span data-i18n="hero.cta">Contact Me</span>
data-i18n-html="key" HTML replacement via innerHTML (preserves <strong> tags) <li data-i18n-html="exp.wahl.b1">...</li>
data-chat-i18n="key" Chat widget text (updated by __setChatLang) <span data-chat-i18n="launcher">Ask Hoang AI</span>

7. Chat Widget

7.1 Frontend (assets/chat-widget.js)

A self-contained vanilla JS module (~420 lines). No framework dependencies. It creates its own DOM from JavaScript and appends it to document.body.

Key Constants

NameValuePurpose
CHAT_API_URL"https://portfolio-ai-proxy.vercel.app/api/chat"Vercel serverless proxy endpoint
MAX_HISTORY_MESSAGES12Only last 12 messages sent per request
CHAT_I18N{ en: {...}, vi: {...} }Bilingual UI strings for the widget

Widget Lifecycle

// initChatWidget() runs on DOMContentLoaded (or immediately if already loaded) 1. createChatElement() // Build full DOM from JS template string ├── .portfolio-chat__panel // Chat panel (header + messages + form) └── .portfolio-chat__launcher // Floating pill button 2. initSuggestedPrompts() // Render 4 prompt pill buttons from CHAT_I18N 3. Bind event listeners: ├── launcher click → toggle .is-open ├── close button click → remove .is-open ├── textarea input → autosize ├── textarea Enter key → submit └── form submit → send message flow 4. window.__setChatLang = fn // Expose for i18n sync

Send Message Flow

1. Validate: non-empty input, not already sending 2. chatState.isSending = true, disable input 3. Push user message to chatState.messages[] 4. Append user bubble to DOM 5. Append "Thinking..." status bubble (in current language) 6. await sendToAssistant() ├── POST to CHAT_API_URL │ { messages: last 12, lang: "en"|"vi" } └── Parse JSON response → return .text 7. Remove status bubble 8. Push assistant response to chatState.messages[] 9. Append assistant bubble (rendered as markdown) 10. chatState.isSending = false, re-enable input

7.2 Markdown Renderer

A custom zero-dependency markdown-to-HTML parser (renderMarkdown()). Built from scratch to avoid CDN dependencies in the widget.

StepOperation
1. HTML-escapeConvert & < > to entities — foundation of XSS prevention
2. Code block extractionTriple-backtick blocks replaced with %%CODEBLOCK_N%% placeholders
3. Inline formattingBold, italic, strikethrough, inline code, links
4. Link protocol checkOnly https:, http:, mailto: allowed
5. Block-level parsingLine-by-line: headings, blockquotes, unordered/ordered lists, horizontal rules
6. Paragraph wrappingRemaining text groups wrapped in <p>; single newlines → <br>
7. Code block restorationPlaceholders swapped back to <pre><code>

7.3 Vercel Serverless Proxy

// Deployed separately at portfolio-ai-proxy.vercel.app Browser (GitHub Pages) | | POST /api/chat { messages: [...], lang: "vi" } v Vercel Function (api/chat.js) | ├── Validate method (POST only) ├── Validate Origin against ALLOWED_ORIGIN env var ├── Validate messages (array, 1-20 items, max 4000 chars each) ├── Inject system prompt (portfolio-aware assistant) ├── Forward to AI provider (OpenAI / Anthropic) └── Return JSON { text: "..." }
The API key never reaches the browser. The Vercel Function reads OPENAI_API_KEY from Vercel environment variables. The browser only communicates with the proxy.

7.4 Security Model

ThreatMitigation
API key exposureKey lives only in Vercel env vars, never in client code
Cross-origin abuseALLOWED_ORIGIN check on every request
XSS via AI outputHTML-escaped before markdown rendering; link protocol whitelist
Request floodingMessage count limit (20); content length limit (4000 chars/message)
Information disclosureNo stack traces in error responses; metadata-only logging

9. Update Guides

9.1 Add or Edit Portfolio Content

  1. Open index.html
  2. Find the section by HTML comment label (e.g. <!-- ══ EXPERIENCE ══ -->)
  3. Edit the HTML directly — the file is self-contained
  4. Add data-i18n="section.key" to any new translatable text
  5. Update both en and vi entries in the I18N dictionary (find the <script> block near the end of the file)
  6. If the new content has metrics/numbers, wrap them in <strong>
  7. Test at 375px, 768px, 1440px widths

9.2 Add a New Translation Key

  1. Choose a key following the section.element convention (e.g. exp.newjob.b1)
  2. Add data-i18n="key" (plain text) or data-i18n-html="key" (text with <strong>) to the HTML element
  3. Add "key": "English text" to I18N.en
  4. Add "key": "Vietnamese text" to I18N.vi
  5. The applyLang() function handles the rest automatically

9.3 Update Chat Widget Context

  1. To update suggested questions: edit the suggested arrays in CHAT_I18N.en and CHAT_I18N.vi in assets/chat-widget.js
  2. To update intro text: edit intro in both CHAT_I18N.en and CHAT_I18N.vi
  3. To update the AI's knowledge: deploy a new version of the Vercel Function with an updated system prompt in api/chat.js, or update data/site-context.json if the function imports it
  4. To update the AI endpoint: change CHAT_API_URL constant in assets/chat-widget.js line 1

9.4 Add or Remove Skill/Tool Tags

  1. Find the skill card in index.html (look for <!-- ══ SKILLS ══ -->)
  2. Add or remove <span class="skill-tag">Name</span> inside the card's <div>
  3. If adding a new card: copy an existing col-md-6 col-lg-3 block, update the number, icon, title, and tags
  4. Update data-i18n attribute on the <h5> and add translations

9.5 Add a Nav Link to Mobile Sidebar

  1. Add the <li><a> to .nav-sidebar__links in the sidebar <aside>
  2. Add the matching <li><a> to the desktop .d-none.d-lg-flex ul
  3. Add data-i18n="nav.newlink" to both
  4. Add translations to I18N.en and I18N.vi
  5. Add data-section="newid" for scroll-spy highlighting

9.6 Change Fonts

  1. Update the Google Fonts <link> in <head> (line ~14)
  2. Search-replace 'Inter' or 'Libre Baskerville' in:
    • index.html (CSS block + inline styles)
    • assets/chat-widget.css
  3. Verify Vietnamese glyph support — test characters: ắ ằ ẳ ẵ ặ ố ồ ổ ỗ ộ ớ ờ ở ỡ ợ
