System Architecture & Technical Specifications

The BOM Dataset Indexer is a modular, version-controlled data indexing platform engineered for legacy database management in manufacturing environments. It provides a universal file and content indexing engine with specialized Bill of Materials (BOM) intelligence.

Core Architecture

The system follows a layered, modular architecture with clear separation of concerns:

Layer Component Technology Description
Presentation index.html / gui.py HTML5 / CSS3 / Tkinter User interfaces for web and desktop deployment
Application Logic parser engine JavaScript / Python File parsing, BOM classification, header recognition
Data Access cache_manager IndexedDB / SQLite Partitioned caching with incremental updates
Infrastructure web_sync / migrate_cache REST / File I/O Cross-platform cache synchronization and migration

Indexing Engine

The indexing pipeline is designed for high-throughput processing of structured and semi-structured Excel data:

  • Directory Crawler — Recursive file-system traversal with configurable include/exclude filters
  • Multi-format Parser — Native support for .xlsx, .xlsm, .xls, .xlsb, and .csv via SheetJS
  • Header Detection — Multi-lingual column header recognition (English, Vietnamese, Chinese) with alias mapping
  • Structured Extraction — Column-aware row parsing mapped to canonical fields (Item, FG, BOM, Qty, Unit, etc.)
  • BOM Classification — Pattern-based categorization: BOM line, BOM header, Mixed BOM report, Non-BOM
  • Inverted Indexing — Full-text search index with metadata enrichment for sub-second queries

Version Control & Schema Management

The platform implements semantic versioning for both data schemas and cache payloads, ensuring backward compatibility and smooth upgrades:

  • Schema Versioning (v3.2.0) — The structural contract that defines how data is organized, parsed, and indexed. Each schema change is tracked with a MAJOR.MINOR.PATCH version.
  • Data Index Version (latest-v8) — The cache payload format identifier. Legacy cache keys (v3 through v7) are automatically migrated on load.
  • Incremental Updates — File signatures (path + size + lastModified) enable differential re-indexing, only processing changed workbooks.
  • Backward Compatibility — The system reads all prior cache formats and transparently upgrades them, with a minimum compatibility floor of v2.0.0.
  • Audit Trail — Each cache write records a generatedAt ISO timestamp, enabling version diffing and rollback analysis.

Performance Characteristics

  • Throughput: Processes thousands of workbooks in minutes with multi-threaded parsing (desktop) or Web Worker parallelism (browser)
  • Cache Partitioning: ~100 MB chunked storage prevents browser quota exhaustion and enables partial cache loads
  • Incremental Indexing: File signature comparison skips unchanged files, reducing re-index time by up to 90%
  • Lazy Rendering: UI tables virtualize to show the first 500 records with progressive loading for remaining rows
  • Cross-Platform: Identical indexing logic in both web (JavaScript) and desktop (Python) implementations

Security & Privacy

  • Zero Server Upload: All file processing executes entirely in the browser or local desktop process. No data leaves the machine.
  • Local-First Architecture: IndexedDB (web) and SQLite (desktop) store all indexed data on the device.
  • Immutable Sources: Original Excel workbooks are never modified, copied, or transmitted.
  • Content Isolation: Worker threads parse files in isolated contexts without DOM or network access.
